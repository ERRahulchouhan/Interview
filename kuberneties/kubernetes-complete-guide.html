Kubernetes – Complete Guide

Har topic short Hinglish me · code · interview Q&A · Windows 11 + Minikube + FastAPI

1. Fundamentals
  • Kubernetes: containers ko cluster me auto deploy, scale, heal karne wala orchestrator (restaurant manager; containers = cooks).
  • Why: self-healing, auto scaling, zero-downtime update, load balancing, config management.
  • Docker vs K8s: Docker = container banata/chalata (1 machine). K8s = bahut machines par containers manage karta hai.
  • Orchestration: scheduling, networking, scaling, health check, update ka automatic control.
  • Control Plane: brain (decisions). Worker Node: muscle (Pods chalte hain).
  • API Server: front door; auth, RBAC, validation, etcd se akela baat karta hai.
  • etcd: key-value DB; cluster ka poora state (Raft, quorum).
  • Scheduler: Pod ke liye best node: Filter, Score, Bind.
  • Controller Manager: reconcile loop: desired state = actual state.
  • Kubelet: node agent; containers start, probes, status report.
  • Kube-proxy: Service ke network rules (iptables/IPVS).
  • Container Runtime: containerd/CRI-O; container actually chalata hai.
kubectl apply -> API Server -> etcd (save)
   -> Scheduler (node choose) -> Kubelet -> Runtime (container start)
   -> Controllers (replicas maintain)

Control Plane: [API Server][etcd][Scheduler][Controller Mgr]
Worker Node  : [Kubelet][Kube-proxy][Runtime] -> [Pod][Pod]
Q: Control plane down ho to apps band? A: Nahi, running Pods chalte hain; naye changes ruk jaate hain.
Q: Pod Pending kyu? A: Scheduler ko fit node nahi mila (resources/taint/PVC).

3. Core Objects

Mandatory: Pod, Deployment, Service. Optional: baaki need ke hisaab se.

  • Pod: smallest unit; 1+ containers, shared IP/storage.
  • ReplicaSet: N Pods hamesha chalu rakhta hai.
  • Deployment: ReplicaSet + rolling update + rollback (stateless apps).
  • StatefulSet: stable name (db-0) + apna storage (databases).
  • DaemonSet: har node par 1 Pod (log/monitor agent).
  • Job / CronJob: ek baar / schedule par kaam.
  • Namespace: isolation. Labels/Selectors: tags se objects jodna. Annotations: extra metadata.
  • ConfigMap: normal config. Secret: sensitive data (base64, encrypted nahi).
  • ServiceAccount: Pod ki identity. ResourceQuota: namespace ki total limit. LimitRange: per-Pod default/limit.
apiVersion: apps/v1
kind: Deployment
metadata: {name: web}
spec:
  replicas: 3                          # kitne Pods
  selector: {matchLabels: {app: web}}  # kin Pods ko manage kare
  template:                            # Pod blueprint
    metadata: {labels: {app: web}}     # selector se match zaroori
    spec:
      containers:
      - {name: web, image: "nginx:1.27", ports: [{containerPort: 80}]}
---
apiVersion: v1
kind: ResourceQuota
metadata: {name: q, namespace: dev}
spec: {hard: {pods: "10", requests.cpu: "2", requests.memory: 4Gi}}
---
apiVersion: v1
kind: LimitRange
metadata: {name: lr, namespace: dev}
spec: {limits: [{type: Container, default: {cpu: 500m, memory: 256Mi}, defaultRequest: {cpu: 100m, memory: 128Mi}}]}
---
apiVersion: batch/v1
kind: CronJob
metadata: {name: hello}
spec:
  schedule: "*/5 * * * *"
  jobTemplate: {spec: {template: {spec: {restartPolicy: OnFailure, containers: [{name: h, image: busybox, command: ["echo","hi"]}]}}}}
kubectl apply -f web.yaml ; kubectl get deploy,rs,pods
kubectl describe pod NAME ; kubectl logs NAME ; kubectl exec -it NAME -- sh
kubectl get pods -l app=web ; kubectl delete -f web.yaml
Q: Deployment vs StatefulSet? A: Interchangeable Pods vs fixed identity + PVC.
Q: Pod delete kiya wapas aaya, kyu? A: ReplicaSet desired count maintain karta hai.
4. Networking
  • Cluster networking: har Pod ka apna IP, bina NAT ke Pod-to-Pod/Node-to-Pod communication.
  • ClusterIP: sirf andar (default). NodePort: NodeIP:30000-32767. LoadBalancer: cloud LB (Minikube: minikube tunnel).
  • Headless: clusterIP: None, DNS se direct Pod IPs (StatefulSet).
  • Ingress: host/path routing + TLS; Ingress Controller (nginx) iske rules chalata hai.
  • CoreDNS: svc.ns.svc.cluster.local resolve. NetworkPolicy: Pod-level firewall. CNI (Calico/Cilium): Pod network banata hai.

Ingress kab: 1 domain par kai services/HTTPS. Service kaafi kab: ek app, internal ya testing.

apiVersion: v1
kind: Service
metadata: {name: web-svc}
spec: {type: ClusterIP, selector: {app: web}, ports: [{port: 80, targetPort: 80}]}
---
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata: {name: web-ing}
spec:
  ingressClassName: nginx
  rules: [{host: app.local, http: {paths: [{path: /, pathType: Prefix, backend: {service: {name: web-svc, port: {number: 80}}}}]}}]
# minikube addons enable ingress
Q: Service Pods kaise dhundhta hai? A: Label selector, Endpoints, kube-proxy routing.
5. Storage
  • Volume: Pod ke andar shared storage. emptyDir: Pod ke saath temporary. hostPath: node folder (sirf test).
  • PV: actual storage. PVC: app ki request. StorageClass + Dynamic Provisioning: PVC aate hi PV auto.
  • Stateful storage: StatefulSet + volumeClaimTemplates. Troubleshoot: PVC Pending to describe pvc Events.
apiVersion: v1
kind: PersistentVolumeClaim
metadata: {name: data-pvc}
spec: {accessModes: [ReadWriteOnce], resources: {requests: {storage: 1Gi}}}   # Minikube "standard" class
---
apiVersion: v1
kind: Pod
metadata: {name: app}
spec:
  containers: [{name: a, image: busybox, command: ["sleep","3600"], volumeMounts: [{name: d, mountPath: /data}]}]
  volumes: [{name: d, persistentVolumeClaim: {claimName: data-pvc}}]
# kubectl get pv,pvc,sc
Q: PVC Pending kyu? A: StorageClass missing, size/accessMode mismatch, provisioner issue.
6. FastAPI Deployment (Project) 
# main.py
import os
from fastapi import FastAPI
app = FastAPI()
@app.get("/")
def root(): return {"msg": "Hello K8s", "env": os.getenv("APP_ENV", "dev")}
@app.get("/health")
def health(): return {"status": "ok"}

# requirements.txt:  fastapi  uvicorn[standard]

# Dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY main.py .
EXPOSE 8000
CMD ["uvicorn","main:app","--host","0.0.0.0","--port","8000"]
docker build -t fastapi-k8s:1.0 .
docker run -p 8000:8000 fastapi-k8s:1.0
minikube image load fastapi-k8s:1.0
# k8s.yaml
apiVersion: v1
kind: ConfigMap
metadata: {name: app-config}
data: {APP_ENV: production}
---
apiVersion: v1
kind: Secret
metadata: {name: app-secret}
stringData: {API_KEY: abc123}
---
apiVersion: apps/v1
kind: Deployment
metadata: {name: fastapi}
spec:
  replicas: 2
  selector: {matchLabels: {app: fastapi}}
  strategy: {rollingUpdate: {maxUnavailable: 0, maxSurge: 1}}
  template:
    metadata: {labels: {app: fastapi}}
    spec:
      containers:
      - name: api
        image: fastapi-k8s:1.0
        imagePullPolicy: IfNotPresent
        ports: [{containerPort: 8000}]
        envFrom: [{configMapRef: {name: app-config}}, {secretRef: {name: app-secret}}]
        readinessProbe: {httpGet: {path: /health, port: 8000}, initialDelaySeconds: 3}
        livenessProbe: {httpGet: {path: /health, port: 8000}, initialDelaySeconds: 10}
        resources: {requests: {cpu: 100m, memory: 128Mi}, limits: {cpu: 500m, memory: 256Mi}}
---
apiVersion: v1
kind: Service
metadata: {name: fastapi-svc}
spec: {type: NodePort, selector: {app: fastapi}, ports: [{port: 80, targetPort: 8000, nodePort: 30080}]}
kubectl apply -f k8s.yaml
minikube service fastapi-svc --url ; curl.exe URL/health
kubectl scale deploy fastapi --replicas=4
kubectl set image deploy/fastapi api=fastapi-k8s:2.0      # rolling update
kubectl rollout status deploy/fastapi
kubectl rollout undo deploy/fastapi                       # rollback
  • Readiness: traffic ke liye ready? Liveness: zinda hai, nahi to restart. requests: guaranteed. limits: max (memory cross = OOMKilled).
Q: Zero-downtime update kaise? A: maxUnavailable 0 + readiness probe.
7. Scaling & Availability
  • Manual: kubectl scale. HPA: CPU/memory par Pods auto. VPA: requests/limits auto. Cluster Autoscaler: nodes add/remove (cloud).
  • Metrics Server: kubectl top + HPA ka data. Load balancing/Self-healing/HA: Service + replicas + multiple nodes.
  • PDB: maintenance me minimum Pods. Affinity/Anti-affinity: Pods saath/alag. Taints/Tolerations: node Pod ko reject/allow. nodeSelector: label wala node. Topology spread: zones me barabar.
minikube addons enable metrics-server
kubectl autoscale deploy fastapi --cpu-percent=60 --min=2 --max=8
kubectl get hpa ; kubectl top pods
# PDB
apiVersion: policy/v1
kind: PodDisruptionBudget
metadata: {name: api-pdb}
spec: {minAvailable: 1, selector: {matchLabels: {app: fastapi}}}
# Anti-affinity (spread across nodes) inside Pod spec
affinity: {podAntiAffinity: {preferredDuringSchedulingIgnoredDuringExecution: [{weight: 100, podAffinityTerm: {topologyKey: kubernetes.io/hostname, labelSelector: {matchLabels: {app: fastapi}}}}]}}
# Taint node, tolerate in Pod
kubectl taint nodes NODE key=gpu:NoSchedule
tolerations: [{key: key, operator: Equal, value: gpu, effect: NoSchedule}]
Q: HPA kaam nahi kar raha? A: Metrics Server missing ya CPU requests set nahi.
8. Security
  • RBAC: Role/ClusterRole = permissions; RoleBinding/ClusterRoleBinding = kisko do. ServiceAccount: Pod identity.
  • Secrets: RBAC + etcd encryption + Vault/External Secrets. Pod Security Standards: privileged/baseline/restricted.
  • SecurityContext: non-root, read-only FS. NetworkPolicy: default deny. Image security: trusted base, Trivy scan, fixed tag. Least privilege: sirf zaroori access.
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata: {name: pod-reader}
rules: [{apiGroups: [""], resources: [pods], verbs: [get, list]}]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata: {name: read-pods}
subjects: [{kind: ServiceAccount, name: api-sa}]
roleRef: {kind: Role, name: pod-reader, apiGroup: rbac.authorization.k8s.io}
---
# container securityContext
securityContext: {runAsNonRoot: true, runAsUser: 1000, allowPrivilegeEscalation: false, readOnlyRootFilesystem: true, capabilities: {drop: [ALL]}}
---
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata: {name: deny-all}
spec: {podSelector: {}, policyTypes: [Ingress]}
# kubectl auth can-i list pods --as=system:serviceaccount:default:api-sa
Q: Secret safe hai? A: Default sirf base64; encryption + RBAC zaroori.

10. CI/CD
  • Flow: Git push, test, docker build, registry push, helm/kubectl deploy, verify, auto rollback. Env-specific config: values-dev.yaml, values-prod.yaml.
  • Rolling: dheere replace. Blue-Green: 2 envs, Service selector switch. Canary: pehle 5-10% traffic. Auto rollback: helm --atomic.
# .github/workflows/deploy.yml
name: ci-cd
on: {push: {branches: [main]}}
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
    - uses: actions/checkout@v4
    - uses: docker/login-action@v3
      with: {username: "${{ secrets.DOCKER_USER }}", password: "${{ secrets.DOCKER_PASS }}"}
    - run: |
        docker build -t ${{ secrets.DOCKER_USER }}/fastapi-k8s:${{ github.sha }} .
        docker push ${{ secrets.DOCKER_USER }}/fastapi-k8s:${{ github.sha }}
    - run: |
        echo "${{ secrets.KUBECONFIG }}" > kube.conf
        KUBECONFIG=kube.conf helm upgrade --install api ./fastapi-chart --set image.tag=${{ github.sha }} --atomic --timeout 2m

// Jenkinsfile
pipeline { agent any; stages {
 stage('Build'){ steps { sh 'docker build -t user/api:${BUILD_NUMBER} .' } }
 stage('Push'){ steps { sh 'docker push user/api:${BUILD_NUMBER}' } }
 stage('Deploy'){ steps { sh 'helm upgrade --install api ./fastapi-chart --set image.tag=${BUILD_NUMBER} --atomic' } } } }
Q: latest tag kyu bura? A: Traceability/rollback nahi; commit SHA use karo.

12. Troubleshooting

Flow: get pods, describe pod (Events), logs --previous, get events.

  • CrashLoopBackOff: app start par crash. Cause: bug, galat env/command, probe fail. Fix: logs --previous.
  • ImagePullBackOff / ErrImagePull: image nahi mila. Cause: galat naam/tag, private registry. Fix: naam check, imagePullSecret, minikube image load.
  • Pending / FailedScheduling: resources kam, taint, PVC unbound. Fix: describe pod, requests kam.
  • OOMKilled: memory limit cross. Fix: limit badhao/leak fix.
  • CreateContainerConfigError: ConfigMap/Secret/key missing.
  • Node NotReady: kubelet/network/disk. describe node.
  • Service not accessible: get endpoints khali? selector mismatch ya readiness fail.
  • DNS failure: kubectl run t --rm -it --image=busybox -- nslookup web-svc; CoreDNS check.
  • PV mount error: PVC Pending, galat claimName, accessMode.
  • App networking: NetworkPolicy block, galat targetPort, port-forward se test.
kubectl describe pod P ; kubectl logs P --previous
kubectl get endpoints ; kubectl get events -A --sort-by=.lastTimestamp
kubectl debug -it P --image=busybox
Scenario: Deploy ke baad 503. Check: Pods Ready? endpoints empty? selector? Turant recover: rollout undo.

15. Interview Preparation

Beginner

Pod vs Container? Pod = 1+ containers, shared network/storage.
Namespace kyu? Isolation + quota.

Intermediate

Liveness vs Readiness vs Startup? Restart / traffic / slow-start protection.
ClusterIP vs NodePort vs LB? Internal / node port / cloud LB.

Advanced

Scheduler kaise decide karta hai? Filter, Score, Bind.
Operator pattern? CRD + reconcile loop.

Scenario

Worker node down: Node controller NotReady mark karta hai, ~5 min baad Pods evict, naye nodes par reschedule.

Production

Traffic spike: HPA, resource requests, Metrics Server, DB bottleneck, PDB + replicas.
Secret git me leak: turant rotate, Sealed/External Secrets ya Vault.
Zero-downtime deploy: rolling + readiness + maxUnavailable 0 + graceful shutdown.

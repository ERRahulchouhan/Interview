Deep Learning: Complete Interview Guide

Every topic from the Master Prompt as a spoken interview answer (about 30–60 seconds each), with diagrams and method names, session by session.

Session 1: Deep Learning Fundamentals

The core vocabulary and mechanics every later topic builds on.

Interview answer (30 sec)

Deep learning is ML with multi-layer neural networks that learn features automatically. A network does a forward pass (a = f(Wx + b)), computes a loss, uses backpropagation (chain rule) to get gradients, and updates weights with gradient descent. I watch train vs validation loss to detect overfitting, and the bias-variance tradeoff guides model size.

Diagram: Training loop of a neural network
Input x→Hidden layers: z = Wx + b, a = f(z)→Output ŷ→Loss L(ŷ, y)→Backprop: ∂L/∂W (chain rule)→Update: W ← W − η∂L/∂W→Repeat per batch/epoch

1. What is Deep Learning?

≈ 70 sec spoken

Deep Learning is a subset of Machine Learning that uses neural networks with many layers to learn patterns directly from raw data. The word 'deep' refers to the number of layers. Each layer transforms its input into a slightly more abstract representation: in an image model, early layers detect edges, middle layers detect shapes, and later layers detect objects like faces or cars.

The key idea is automatic feature learning. In traditional ML an engineer designs features by hand, for example 'number of corners in the image'. In deep learning the network discovers the features itself by minimizing a loss with gradient descent. That is why it works so well on unstructured data: images, text, audio and video.

It became practical in the last decade because of three things: large datasets, GPUs for fast matrix math, and better techniques such as ReLU, dropout, batch norm and Adam.

Real examples: face unlock, Google Translate, voice assistants, ChatGPT, fraud detection, self-driving perception.

Methods
nn.Module, nn.Sequential, keras.Sequential
Interview tip: Deep learning is not always better. On small tabular data, gradient boosting (XGBoost) often wins, and I would say that to show judgment.

2. AI vs ML vs Deep Learning

≈ 55 sec spoken

These are nested. Artificial Intelligence is the broad goal of making machines behave intelligently, and includes rule-based systems, search, planning and expert systems. Machine Learning is a subset of AI where the system learns patterns from data instead of being explicitly programmed. Deep Learning is a subset of ML that uses multi-layer neural networks.

A simple example: a chess engine using hand-written rules and search is AI but not ML. A spam filter using Naive Bayes or logistic regression on hand-built features is ML. An email classifier using a Transformer that learns its own features from raw text is Deep Learning.

I picture it as three concentric circles: AI outside, ML inside it, DL in the centre. Generative AI and LLMs sit inside deep learning.

Methods
sklearn.linear_model.LogisticRegression (ML) vs torch.nn.Module (DL)
Interview tip: Common trap: saying deep learning is a separate field. It is a subset.

3. Traditional ML vs Deep Learning

≈ 55 sec spoken

The biggest difference is feature engineering. Traditional ML (random forest, SVM, XGBoost) needs hand-crafted features and works well with small to medium data, trains in seconds on a CPU, and is easy to interpret. Deep learning learns features itself, needs large data and GPUs, takes longer to train, and is harder to interpret, but its accuracy keeps improving as data grows, while classical models plateau.

For tabular business data with a few thousand rows I would start with gradient boosting. For images, audio, text or video, I would use deep learning, ideally a pretrained model with transfer learning.

Other differences: DL has many more hyperparameters, needs more careful tuning, and has higher deployment cost. Classical models give faster baselines and feature importance out of the box.

Methods
sklearn RandomForestClassifier, xgboost.XGBClassifier vs nn.Module, model.fit()
Interview tip: Good follow-up answer: always build a simple baseline first, then justify the deep model by the metric gain.

4. Biological vs artificial neurons

≈ 50 sec spoken

A biological neuron receives electrical signals through dendrites, sums them in the cell body, and if the total crosses a threshold it fires a signal along the axon to other neurons through synapses. Synapse strength determines how much each input matters, and learning changes those strengths.

An artificial neuron copies this loosely: inputs x are multiplied by weights w (synapse strength), summed with a bias b (threshold shift), and passed through an activation function f. Output a = f(w·x + b). Training adjusts the weights.

The analogy is only an inspiration. Real brains are far more complex, with spiking, chemistry and feedback, and they do not learn through backpropagation. Artificial networks are really differentiable function approximators.

Methods
layer = nn.Linear(n_in, n_out); a = torch.relu(layer(x))
Interview tip: Say clearly it is an inspiration, not a faithful model.

5. Perceptron

≈ 55 sec spoken

The perceptron is the simplest neural network, a single neuron with a step activation: ŷ = 1 if w·x + b > 0 else 0. It is a linear binary classifier that draws a straight line (hyperplane) between two classes.

Learning rule: for each sample, if the prediction is wrong update w ← w + η(y − ŷ)x and b ← b + η(y − ŷ). If the data is linearly separable, the perceptron convergence theorem guarantees it finds a separating line in finite steps.

Limitation: it cannot solve XOR because XOR is not linearly separable. That limitation caused the first 'AI winter' and was solved by stacking neurons into multilayer networks with non-linear activations.

Example: AND and OR gates are learnable by one perceptron; XOR needs at least one hidden layer.

Methods
sklearn.linear_model.Perceptron(); NumPy: np.dot(w, x) + b
Interview tip: Expect: 'Why can't it solve XOR?'

6. Artificial Neural Network (ANN)

≈ 50 sec spoken

An ANN is a set of layers of neurons where each neuron is connected to neurons in the next layer, and it learns a mapping from inputs to outputs. It is also called an MLP or feed-forward network. Because of non-linear activations, it can approximate very complex functions: the universal approximation theorem says a network with one hidden layer and enough neurons can approximate any continuous function.

Training loop: forward pass to get predictions, compute the loss, backpropagate to get gradients, and update weights with an optimizer. Repeat for many epochs while monitoring validation loss.

Use cases: tabular prediction (house prices, churn), simple classification, and as the fully connected head of CNNs and Transformers.

Methods
nn.Sequential(nn.Linear(10, 64), nn.ReLU(), nn.Linear(64, 1)); keras.Sequential([Dense(64, activation='relu'), Dense(1)])
Interview tip: Mention that depth gives hierarchical features, but too much depth without care causes vanishing gradients.

7. Neural network architecture

≈ 40 sec spoken

Architecture means the design of the network: how many layers, how many neurons per layer, which activation functions, which layer types (dense, convolution, recurrent, attention), and how layers are connected (plain stack, skip connections).

These are hyperparameters I choose before training. Wider layers add capacity per level, deeper layers add hierarchical features. Too small gives underfitting, too large gives overfitting and cost.

In practice I do not invent an architecture from scratch. I pick a known one for the data type: MLP for tabular, CNN/ResNet for images, LSTM or Transformer for sequences. Then I adjust size using validation results.

Methods
nn.Module with __init__ (layers) and forward() (data flow); model.summary() in Keras; torchinfo.summary(model)
Interview tip: Number of parameters is a good quick size check.

8. Input, hidden and output layers

≈ 40 sec spoken

The input layer receives the raw features; it does no computation, and its size equals the number of features (784 for a flattened 28×28 image). Hidden layers sit in between, and they do the learning: each computes a = f(Wx + b) and builds more abstract features. The output layer produces the prediction, and its size and activation depend on the task.

Output design: regression uses 1 neuron with linear activation; binary classification uses 1 neuron with sigmoid; multiclass uses k neurons with softmax.

Example: for MNIST, 784 inputs → 128 hidden (ReLU) → 10 outputs (softmax).

Methods
nn.Linear(784, 128), nn.ReLU(), nn.Linear(128, 10); keras Dense(10, activation='softmax')
Interview tip: Remember: PyTorch CrossEntropyLoss expects raw logits, not softmax outputs.

9. Weights and biases

≈ 45 sec spoken

Weights are the learnable numbers that scale each input; a large positive weight means that input strongly increases the neuron's output. The bias is a learnable offset that shifts the activation, letting the neuron fire even when all inputs are zero. Together they are the model's parameters, and training is the process of finding good values for them.

Count example: a layer from 784 inputs to 128 neurons has 784×128 weights plus 128 biases = 100,480 parameters.

Initialization matters. All zeros makes every neuron identical (the symmetry problem). Use Xavier/Glorot for tanh or sigmoid, and He initialization for ReLU, to keep activations and gradients at a stable scale.

Methods
layer.weight, layer.bias, model.parameters(), nn.init.kaiming_normal_(), nn.init.xavier_uniform_()
Interview tip: Bias is not the same as the bias in bias-variance; clarify that if asked.

10. Activation functions

≈ 40 sec spoken

An activation function is a non-linear function applied to a neuron's weighted sum. It is essential: without it, stacking layers collapses to one linear transformation, so the network could never learn curves or complex boundaries.

Choices: ReLU (max(0, x)) is the default for hidden layers: cheap and avoids vanishing gradients, but neurons can die. Leaky ReLU fixes that. GELU is the standard in Transformers. Sigmoid outputs a probability for binary classification, softmax for multiclass, and linear for regression outputs.

Sigmoid and tanh saturate for large inputs, which gives near-zero gradients and slow learning in deep nets.

Methods
nn.ReLU(), nn.LeakyReLU(0.01), nn.GELU(), nn.Sigmoid(), nn.Softmax(dim=1); keras layers.Activation('relu')
Interview tip: Typical question: why not use ReLU on the output layer for classification?

11. Forward propagation

≈ 50 sec spoken

Forward propagation is the process of pushing an input through the network, layer by layer, to get a prediction. For each layer: z = W·a_prev + b, then a = f(z). The final activation is the prediction ŷ, and we compare it with the true label to compute the loss.

Tiny example: input x = 2, weight w = 0.5, bias b = 1 → z = 0.5·2 + 1 = 2, ReLU(2) = 2. Next layer takes 2 as its input, and so on.

It is just matrix multiplication, so a whole batch is processed at once, which is why GPUs are so effective. During forward pass, frameworks also store intermediate values (z and a) because backpropagation needs them.

Methods
outputs = model(x); torch.matmul(X, W) + b; model.eval() with torch.no_grad() for inference
Interview tip: In training mode dropout and batch norm behave differently from eval mode.

12. Loss functions

≈ 45 sec spoken

A loss function is a single number that measures how wrong the model's prediction is. Training means minimizing this number. It must be differentiable so gradients can flow.

Choice by task: regression uses MSE (penalizes large errors) or MAE/Huber (robust to outliers). Binary classification uses binary cross-entropy. Multiclass uses categorical cross-entropy. Imbalanced data may use class-weighted loss or focal loss.

Cross-entropy: L = −Σ y·log(ŷ). It punishes confident wrong predictions heavily: predicting 0.01 for the true class gives a loss of 4.6, but predicting 0.9 gives only 0.1.

The loss is not the same as the metric: loss is for the optimizer, metrics (accuracy, F1) are for humans and business.

Methods
nn.MSELoss(), nn.CrossEntropyLoss(), nn.BCEWithLogitsLoss(); keras loss='sparse_categorical_crossentropy'
Interview tip: Mistake to avoid: applying softmax before CrossEntropyLoss in PyTorch.

13. Backpropagation

≈ 55 sec spoken

Backpropagation is the algorithm that computes the gradient of the loss with respect to every weight efficiently. It applies the chain rule from the output layer backward to the input, reusing the values saved in the forward pass.

Intuition: the loss depends on the output, which depends on the last layer's weights, which depend on the previous layer, and so on. The chain rule multiplies local derivatives along that path: ∂L/∂w = ∂L/∂a · ∂a/∂z · ∂z/∂w.

For softmax with cross-entropy, the output error is simply ŷ − y, and it is propagated back: δ_prev = (Wᵀδ) ⊙ f′(z). The weight gradient is δ times the previous activation.

Backprop only computes gradients; the optimizer then uses them to update weights. Frameworks do it automatically using autograd on the computational graph.

Methods
loss.backward(), tf.GradientTape(), tensor.grad, optimizer.zero_grad()
Interview tip: Common bug: forgetting optimizer.zero_grad(), so gradients accumulate across batches.

14. Gradient descent

≈ 45 sec spoken

Gradient descent is the optimization method that minimizes the loss by repeatedly moving the weights in the direction opposite to the gradient: w ← w − η·∂L/∂w. The gradient points uphill, so we go downhill, and η (learning rate) controls the step.

Variants: batch GD uses all data per step (stable but slow), stochastic GD uses one sample (noisy), and mini-batch GD uses a small batch such as 32–256, the practical standard. Advanced optimizers like Momentum, RMSProp and Adam improve on the plain version.

Challenges: local minima and saddle points, plateaus, and bad learning rates. In deep networks the loss surface is non-convex, but in practice SGD finds good solutions.

Methods
optim.SGD(params, lr=0.01), optimizer.step(), optim.Adam()
Interview tip: Analogy: walking down a foggy mountain by feeling the slope under your feet.

15. Learning rate

≈ 40 sec spoken

The learning rate is the step size of each weight update, and it is the most important hyperparameter. Too high: loss oscillates or diverges to NaN. Too low: training is very slow and may get stuck. Just right: the loss decreases smoothly.

Typical starting points: Adam 1e-3 (3e-4 is a safe choice), SGD 0.01–0.1, and fine-tuning pretrained models 1e-5 to 5e-5.

Techniques: learning-rate schedulers (step decay, cosine decay, one-cycle), warmup for Transformers, and a learning-rate range test to find a good value. Reduce on plateau is a simple, robust choice.

Methods
optim.Adam(lr=1e-3), lr_scheduler.ReduceLROnPlateau(), CosineAnnealingLR(), OneCycleLR()
Interview tip: If loss becomes NaN, the first suspect is a learning rate that is too high.

16. Epoch, batch size and iteration

≈ 45 sec spoken

An epoch is one full pass over the entire training dataset. A batch is the group of samples processed together before one weight update. An iteration is one update step, that is one batch processed. Iterations per epoch = ceil(N / batch_size).

Example: 1000 samples with batch size 100 gives 10 iterations per epoch; 20 epochs give 200 weight updates.

Batch size trade-off: small batches give noisy gradients, which can regularize and generalize well, but use GPUs less efficiently. Large batches are faster per epoch and stable but need more memory, and may need a higher learning rate and can generalize slightly worse. 32–128 is a common start.

Methods
DataLoader(ds, batch_size=32, shuffle=True); model.fit(X, y, batch_size=32, epochs=20)
Interview tip: Always shuffle training data each epoch, but not validation data.

17. Parameters vs hyperparameters

≈ 40 sec spoken

Parameters are values the model learns from data during training: weights and biases. Hyperparameters are settings I choose before training that control how learning happens: learning rate, batch size, number of layers and neurons, activation, dropout rate, optimizer, epochs, weight decay.

Parameters are updated by gradient descent. Hyperparameters are tuned by experiments on the validation set, using grid search, random search or Bayesian optimization such as Optuna.

Rule: never tune hyperparameters on the test set, as that leaks information and gives an over-optimistic score. Use train for fitting, validation for tuning, test for the final report.

Methods
model.parameters() vs optim.Adam(lr=...); optuna.create_study(), study.optimize()
Interview tip: Random search often beats grid search for the same budget.

18. Underfitting and overfitting

≈ 45 sec spoken

Underfitting means the model is too simple or under-trained: both training and validation errors are high. Overfitting means the model memorizes the training data, including noise: training error is low but validation error is much higher.

How to detect: plot training and validation loss. If both are high and close, it is underfitting. If training keeps falling while validation rises, it is overfitting.

Fixes for underfitting: bigger model, more features, train longer, lower regularization. Fixes for overfitting: more data, data augmentation, dropout, L2/weight decay, early stopping, a smaller model, or transfer learning.

The goal is a model that generalizes: good performance on unseen data.

Methods
nn.Dropout(0.3), optim.AdamW(weight_decay=1e-2), EarlyStopping(patience=5), transforms augmentation
Interview tip: Interviewers love: 'Training accuracy 99%, validation 70%, what do you do?'

19. Bias-variance tradeoff

≈ 55 sec spoken

Total error splits into bias², variance and irreducible noise. Bias is error from overly simple assumptions: the model misses real patterns (underfitting). Variance is error from sensitivity to the training set: the model changes a lot with different data (overfitting).

A simple model like linear regression has high bias and low variance. A very deep, unregularized network has low bias and high variance. As complexity increases, bias falls and variance rises, so there is a sweet spot with the lowest total error.

Ways to manage it: regularization and more data reduce variance; a richer model and better features reduce bias; ensembles and cross-validation help estimate and control the balance.

Modern large networks show 'double descent', where very large models can generalize well, but the basic tradeoff remains the right mental model for interviews.

Methods
sklearn.model_selection.cross_val_score(), learning_curve(); compare train vs val loss
Interview tip: Say which side a given symptom points to: high train error means bias, large train-val gap means variance.

Session 2: Mathematics for Deep Learning

Just enough math to understand why networks train, taught with small examples.

Interview answer (30 sec)

Linear algebra gives us the data structures and matrix multiplication of each layer. Calculus gives gradients: the chain rule over the computational graph is backpropagation. Probability gives us softmax outputs, cross-entropy as the loss, and KL divergence for comparing distributions.

Diagram: From math to learning
Vectors / matrices→Matrix multiply (forward)→Derivatives→Chain rule→Gradients→Backprop

Linear Algebra

1. Scalars, vectors, matrices

≈ 30 sec spoken

A scalar is one number, a vector is a 1-D array, a matrix is a 2-D grid, and a tensor generalizes to any number of dimensions. In deep learning, one input sample is a vector, a batch is a matrix, an image batch is a 4-D tensor (N, C, H, W), and weights are matrices. Knowing shapes is the number one debugging skill: most errors are shape mismatches.

2. Matrix multiplication

≈ 20 sec spoken

Matrix multiplication combines rows of A with columns of B; shapes (m×n)·(n×p) give (m×p). A dense layer is exactly Y = XW + b, so a whole batch goes through a layer in one multiplication, which is why GPUs make training fast. Note it is not commutative: AB ≠ BA.

Methods
np.dot(), @, torch.matmul()

3. Dot product

≈ 20 sec spoken

The dot product is the sum of element-wise products, a·b = Σ aᵢbᵢ. It measures how aligned two vectors are, so it acts as a similarity score. A neuron computes w·x + b, and in attention the score between a query and a key is their dot product, scaled by √d.

4. Transpose

≈ 15 sec spoken

The transpose flips rows and columns, so (m×n) becomes (n×m). We use it to align shapes, for example QKᵀ in attention, and in backpropagation where the gradient to the previous layer is Wᵀδ. Property: (AB)ᵀ = BᵀAᵀ.

Methods
arr.T, torch.transpose()

5. Eigenvalues and eigenvectors

≈ 20 sec spoken

For a matrix A, an eigenvector v satisfies Av = λv: the matrix only stretches it by λ without changing its direction. PCA uses eigenvectors of the covariance matrix as principal components. In RNNs, eigenvalues of the recurrent weight matrix above 1 cause exploding gradients and below 1 cause vanishing gradients.

Methods
np.linalg.eig()

6. Matrix operations

≈ 20 sec spoken

The everyday operations are addition, element-wise (Hadamard) product, scalar multiplication, inverse and broadcasting. Broadcasting lets a bias vector be added to every row of a batch without copying. Vectorized operations are far faster than Python loops, so I avoid loops over samples.

Calculus

7. Derivatives

≈ 20 sec spoken

A derivative is the rate of change of a function: how much the output moves when the input changes slightly. In training, it tells us how the loss changes if we nudge a weight. If the derivative is positive, decreasing the weight lowers the loss. Example: d/dx x² = 2x.

8. Partial derivatives

≈ 20 sec spoken

When a function depends on many variables, a partial derivative measures change with respect to one variable while holding the others fixed. The loss depends on millions of weights, so we compute ∂L/∂wᵢ for each weight. Collected together, they form the gradient.

9. Chain rule

≈ 20 sec spoken

The chain rule gives the derivative of a composite function: if y = f(g(x)), then dy/dx = f′(g(x))·g′(x). A neural network is a chain of functions (layer after layer), so the loss gradient for an early weight is a product of local derivatives along the path. This is exactly backpropagation.

Methods
autograd applies it inside loss.backward()

10. Gradients

≈ 20 sec spoken

The gradient is the vector of all partial derivatives of the loss. It points in the direction of steepest increase, so we move opposite to it: w ← w − η∇L. Its magnitude matters too: tiny gradients mean vanishing gradients, huge ones mean exploding gradients, fixed with clipping.

Methods
x.requires_grad_(), torch.autograd.grad()

11. Gradient computation

≈ 20 sec spoken

To compute a gradient manually: take a single neuron with ŷ = σ(wx + b) and loss (ŷ − y)². Then ∂L/∂w = 2(ŷ − y)·σ′(z)·x. In practice, autograd does it, and I verify custom layers with gradient checking: compare to the numerical (L(w+ε) − L(w−ε))/2ε.

12. Computational graphs

≈ 20 sec spoken

A computational graph represents a calculation as nodes (operations) and edges (tensors). The forward pass builds it and stores intermediate values; the backward pass walks it in reverse applying the chain rule at each node. PyTorch builds it dynamically on the fly; TensorFlow 1 used static graphs, and tf.function compiles one.

Methods
tf.GradientTape(), loss.backward()

Probability and Statistics

13. Probability distributions

≈ 20 sec spoken

A distribution describes how likely each outcome is. Classification outputs are categorical distributions (softmax), regression noise is often assumed Gaussian, and Bernoulli models binary outcomes. Training with cross-entropy is maximum likelihood estimation: we pick the weights that make the observed data most probable.

14. Mean and variance

≈ 20 sec spoken

The mean is the average and the variance is the average squared distance from the mean; standard deviation is its square root. We use them to standardize inputs ((x − μ)/σ), in batch normalization, and to choose initial weight scales like He (variance 2/n).

Methods
np.mean(), np.var(), x.mean(), x.std()

15. Normal distribution

≈ 20 sec spoken

The normal (Gaussian) distribution is the bell curve defined by mean and variance, with about 68% of values within one standard deviation. Weights are initialized from it, VAEs sample latents from it, and diffusion models add Gaussian noise step by step. Central Limit Theorem explains why it appears so often.

16. Conditional probability

≈ 15 sec spoken

P(A|B) is the probability of A given that B happened, equal to P(A∩B)/P(B). A classifier is modelling P(class | input). Language models factorize text probability as a product of P(next word | previous words).

17. Bayes theorem

≈ 20 sec spoken

Bayes theorem: P(A|B) = P(B|A)·P(A) / P(B). It updates a prior belief with new evidence. Example: a disease test with 99% accuracy for a 1% prevalent disease: a positive result still gives only about 50% chance of disease, because the prior is low. It underlies Naive Bayes and Bayesian methods.

18. Entropy and cross-entropy

≈ 25 sec spoken

Entropy H(p) = −Σ p log p measures uncertainty in a distribution. Cross-entropy H(p, q) = −Σ p log q measures the cost of using the predicted distribution q when truth is p. With one-hot labels it becomes −log(prob of true class), the standard classification loss, and it is minimized when q equals p.

Methods
scipy.stats.entropy(), F.cross_entropy()

19. KL divergence

≈ 20 sec spoken

KL(p‖q) = Σ p log(p/q) measures how much q differs from p; it is zero only when they are identical and it is not symmetric. Cross-entropy = entropy + KL. Used in VAEs (keeping latents near a normal prior), knowledge distillation, and RLHF to keep a model close to a reference.

Methods
nn.KLDivLoss(), F.kl_div()

Session 3: Activation Functions

Non-linearities that let networks model complex patterns. Each is compared on gradient behaviour and best use.

Interview answer (30 sec)

Activations add non-linearity; without them many layers equal one linear layer. I use ReLU/GELU in hidden layers, sigmoid for binary output, softmax for multiclass, and linear for regression. Sigmoid/tanh saturate and cause vanishing gradients; ReLU can die, so Leaky ReLU or GELU is the fix.

Diagram: Inside one neuron
Inputs x→z = w·x + b→Activation f(z)→Output a → next layer

1. Binary Step

≈ 20 sec spoken

The step function outputs 1 if x ≥ 0 else 0. It was used in the original perceptron. Its gradient is zero everywhere except at the jump, so backpropagation cannot train with it. That is why it was replaced by smooth functions like sigmoid.

2. Linear

≈ 20 sec spoken

A linear activation f(x) = x has constant gradient 1. It is used on the output layer for regression, where we want any real number. Using it in hidden layers is pointless because stacked linear layers collapse into a single linear map.

3. Sigmoid

≈ 20 sec spoken

Sigmoid σ(x) = 1/(1 + e⁻ˣ) maps to (0, 1), so it reads as a probability. I use it as the output for binary classification (with BCE). Drawbacks: saturates for large |x| giving vanishing gradients, and the output is not zero-centred, so I avoid it in hidden layers. Maximum gradient is 0.25.

Methods
torch.sigmoid(), nn.Sigmoid()

4. Tanh

≈ 15 sec spoken

Tanh maps to (−1, 1) and is zero-centred, which makes optimization easier than sigmoid. Its gradient is at most 1. It still saturates and causes vanishing gradients in deep networks. It is common inside LSTM and GRU cells.

Methods
nn.Tanh()

5. ReLU

≈ 25 sec spoken

ReLU = max(0, x). It is cheap, does not saturate for positive values, and gives sparse activations, so it is the default for hidden layers. Problem: dying ReLU, where a neuron always outputs 0 because its inputs are negative, and its gradient is then zero forever. Use a smaller learning rate, He initialization, or Leaky ReLU.

Methods
nn.ReLU(), F.relu()

6. Leaky ReLU

≈ 20 sec spoken

Leaky ReLU gives a small slope on the negative side: f(x) = x if x > 0 else 0.01x. That keeps a non-zero gradient so neurons cannot die. It costs almost nothing extra and is a safe replacement for ReLU when many units are dead.

Methods
nn.LeakyReLU(0.01)

7. PReLU

≈ 15 sec spoken

Parametric ReLU is Leaky ReLU with the negative slope α learned during training instead of fixed. It adds a few parameters and can improve accuracy on large image models, but may overfit on small datasets.

Methods
nn.PReLU()

8. ELU

≈ 15 sec spoken

ELU is x for positive input and α(eˣ − 1) for negative. It is smooth, has negative outputs that push mean activation to zero, and avoids dead neurons. The exponential makes it slightly slower than ReLU.

Methods
nn.ELU()

9. SELU

≈ 20 sec spoken

SELU is a scaled ELU with fixed constants such that activations self-normalize to mean 0 and variance 1 across layers in a feed-forward net. It needs LeCun-normal initialization and alpha-dropout, and works best in plain MLPs; it is less common in modern CNNs and Transformers.

Methods
nn.SELU()

10. GELU

≈ 15 sec spoken

GELU(x) = x·Φ(x), where Φ is the Gaussian CDF; it weights an input by how likely it is to be positive. It is smooth and non-monotonic, and is the standard in BERT, GPT and Vision Transformers.

Methods
nn.GELU()

11. Swish (SiLU)

≈ 15 sec spoken

Swish is x·sigmoid(x). Like GELU it is smooth and non-monotonic, and often slightly beats ReLU in deep networks. Used in EfficientNet and many modern models; PyTorch calls it SiLU.

Methods
nn.SiLU()

12. Softmax

≈ 20 sec spoken

Softmax turns a vector of scores (logits) into probabilities: eᶻⁱ / Σ eᶻʲ, summing to 1. It is for the multiclass output layer. For numerical stability subtract the maximum logit first. In PyTorch, CrossEntropyLoss applies log-softmax internally, so feed it raw logits.

Methods
nn.Softmax(dim=1), F.softmax()

Session 4: Loss Functions

The objective that defines what 'good' means for the model. Choice depends on the task.

Interview answer (30 sec)

The loss defines the objective. MSE/MAE/Huber for regression, BCE for binary, cross-entropy for multiclass, focal loss or class weights for imbalance, KL for distributions. In PyTorch I pass raw logits to CrossEntropyLoss or BCEWithLogitsLoss for numerical stability.

Diagram: Choosing the loss
Task?→Regression: MSE / MAE / Huber→Binary: BCE→Multiclass: Cross-Entropy→Imbalanced: Focal / class weights

1. Mean Squared Error (MSE)

≈ 20 sec spoken

MSE = (1/n)Σ(y − ŷ)². Squaring punishes large errors heavily and gives a smooth gradient, so it is the default for regression. It is sensitive to outliers; if the data has them I switch to MAE or Huber. Result units are squared, so RMSE is easier to explain.

Methods
nn.MSELoss(), loss='mse'

2. Mean Absolute Error (MAE)

≈ 20 sec spoken

MAE = (1/n)Σ|y − ŷ|. It is robust to outliers and in the same units as the target, but its gradient is constant, and not defined at zero, which can make convergence noisy near the minimum. It predicts the median, while MSE predicts the mean.

Methods
nn.L1Loss()

3. Huber Loss

≈ 15 sec spoken

Huber is quadratic for errors smaller than δ and linear beyond it. You get MSE's smooth gradient near the optimum and MAE's outlier robustness for large errors. δ is a hyperparameter. Good choice for noisy regression and reinforcement learning (DQN).

Methods
nn.HuberLoss(), nn.SmoothL1Loss()

4. Binary Cross Entropy

≈ 20 sec spoken

BCE = −[y log p + (1 − y) log(1 − p)]. It is for two-class problems with a sigmoid output. Confident wrong predictions are punished strongly. In PyTorch use BCEWithLogitsLoss on raw logits, which is more numerically stable than sigmoid followed by BCELoss.

Methods
nn.BCEWithLogitsLoss(), BinaryCrossentropy()

5. Categorical Cross Entropy

≈ 15 sec spoken

Categorical cross-entropy is −Σ yᵢ log pᵢ with one-hot labels and softmax outputs, so it reduces to −log(probability of the true class). It is the standard multiclass loss and corresponds to maximum likelihood.

Methods
nn.CrossEntropyLoss(), CategoricalCrossentropy()

6. Sparse Categorical Cross Entropy

≈ 15 sec spoken

It is the same loss, but the labels are integers (0, 1, 2…) instead of one-hot vectors. This saves memory when there are many classes, such as a vocabulary of 50,000 tokens. PyTorch's CrossEntropyLoss already takes integer labels.

Methods
SparseCategoricalCrossentropy()

7. Hinge Loss

≈ 20 sec spoken

Hinge loss = max(0, 1 − y·f(x)) with labels in {−1, +1}. It is zero when the sample is correctly classified with a margin of at least 1, so it focuses on hard or misclassified points. It comes from SVMs and gives max-margin classifiers but does not give probabilities.

Methods
nn.MultiMarginLoss(), keras Hinge()

8. Focal Loss

≈ 20 sec spoken

Focal loss = −(1 − p)^γ · log p. The factor (1 − p)^γ shrinks the loss of well-classified easy examples, so training concentrates on hard ones. It was designed for object detection (RetinaNet), where background examples dominate. γ = 2 is typical, and α can weight the classes.

Methods
torchvision.ops.sigmoid_focal_loss()

9. KL Divergence

≈ 20 sec spoken

KL loss measures the gap between predicted distribution and a target distribution. It is used in VAEs to regularize the latent space, in knowledge distillation to match a student to a teacher, and in RLHF to limit drift from a reference model. It is not symmetric.

Methods
nn.KLDivLoss()

Which to use

10. Regression

≈ 15 sec spoken

For regression I start with MSE, switch to MAE or Huber if there are outliers, and use a linear output activation. Evaluate with MAE or RMSE in business units.

11. Binary classification

≈ 15 sec spoken

One output neuron with sigmoid and binary cross-entropy (BCEWithLogitsLoss). Use class weights or focal loss if classes are imbalanced, and choose the threshold using precision-recall trade-offs, not blindly 0.5.

12. Multiclass classification

≈ 15 sec spoken

k output neurons with softmax and categorical or sparse categorical cross-entropy. In PyTorch, pass raw logits to CrossEntropyLoss. For multi-label problems (several classes at once), use sigmoid per class with BCE instead.

13. Imbalanced datasets

≈ 15 sec spoken

Options: class-weighted cross-entropy, focal loss, oversampling (SMOTE) or undersampling, and weighted samplers. Evaluate with precision, recall, F1 and PR-AUC rather than accuracy. Example: with 1% fraud, a model predicting 'no fraud' always is 99% accurate but useless.

Session 5: Optimization Algorithms

How weights are updated. Compared on convergence speed, memory, and practicality.

Interview answer (30 sec)

Optimizers decide how gradients become updates. Mini-batch SGD is the baseline; momentum smooths it; RMSProp and Adam adapt per-parameter rates; AdamW decouples weight decay and is the default for Transformers. Schedulers like warmup plus cosine decay improve convergence.

Diagram: Optimizer step
Gradient g→Momentum (m) / adaptive scale (v)→Adam update→LR scheduler (warmup → cosine)→New weights

1. Batch Gradient Descent

≈ 20 sec spoken

Batch GD computes the gradient on the whole dataset for each update. The path is smooth and stable and converges to the minimum for convex problems, but each step is slow, memory-heavy and cannot handle huge datasets. Rarely used in deep learning.

Methods
DataLoader(batch_size=len(ds))

2. Stochastic Gradient Descent

≈ 15 sec spoken

SGD updates after every single sample. Updates are very fast and noisy, and the noise helps escape shallow local minima and saddle points, but the loss oscillates and vectorization is poor. In practice people say 'SGD' for mini-batch SGD.

Methods
optim.SGD(), batch_size=1

3. Mini-Batch Gradient Descent

≈ 15 sec spoken

Mini-batch GD uses 32–256 samples per update. It balances stable gradient estimates with fast updates and uses GPU parallelism well. This is the standard in deep learning, and the batch size is a hyperparameter.

Methods
DataLoader(batch_size=32, shuffle=True)

4. Momentum

≈ 20 sec spoken

Momentum keeps a velocity: v = βv + g, w ← w − ηv, with β around 0.9. It accumulates consistent gradient directions and damps oscillations in steep, narrow valleys, so convergence is faster. Like a ball rolling downhill gathering speed.

Methods
optim.SGD(momentum=0.9)

5. Nesterov Accelerated Gradient

≈ 15 sec spoken

NAG calculates the gradient at the look-ahead position (w − βv) rather than the current one. That lets it correct its course earlier and overshoot less than classic momentum. Same cost, usually slightly better convergence.

Methods
optim.SGD(momentum=0.9, nesterov=True)

6. AdaGrad

≈ 20 sec spoken

AdaGrad gives each parameter its own learning rate, divided by the square root of the sum of its past squared gradients. Rare features get larger updates, so it suits sparse data like text. Weakness: the sum only grows, so the learning rate eventually shrinks to nearly zero.

Methods
optim.Adagrad()

7. RMSProp

≈ 15 sec spoken

RMSProp fixes AdaGrad's decay by using an exponential moving average of squared gradients, so the effective learning rate does not vanish. It works well for non-stationary problems such as RNNs. Typical decay 0.9.

Methods
optim.RMSprop()

8. Adam

≈ 25 sec spoken

Adam combines momentum (first moment m) and RMSProp (second moment v) with bias correction: w ← w − η·m̂/(√v̂ + ε). Defaults β₁ = 0.9, β₂ = 0.999, lr = 1e-3. It converges quickly with little tuning, but needs memory for two extra values per parameter and sometimes generalizes slightly worse than tuned SGD.

Methods
optim.Adam(lr=1e-3)

9. AdamW

≈ 15 sec spoken

AdamW decouples weight decay from the gradient update, applying it directly to the weights. In plain Adam, L2 regularization interacts with the adaptive scaling and becomes less effective. AdamW is the default for Transformers and fine-tuning.

Methods
optim.AdamW(weight_decay=0.01)

10. Nadam

≈ 15 sec spoken

Nadam is Adam with Nesterov momentum, giving a look-ahead step. It sometimes converges a little faster than Adam, particularly with noisy gradients, but the gain is usually small.

Methods
optim.NAdam()

11. Learning Rate Scheduling

≈ 15 sec spoken

A scheduler changes the learning rate during training: step decay, exponential decay, ReduceLROnPlateau, cosine annealing, or one-cycle. High at first for fast progress and low later for fine convergence. It often improves final accuracy for free.

Methods
lr_scheduler.StepLR(), ReduceLROnPlateau(), OneCycleLR()

12. Warmup and Cosine Decay

≈ 20 sec spoken

Warmup starts with a tiny learning rate and increases it linearly over the first few hundred or thousand steps, which stabilizes Adam while its moment estimates are still noisy. Cosine decay then lowers the rate smoothly toward zero. This pair is standard for Transformer training.

Methods
CosineAnnealingLR(), transformers.get_cosine_schedule_with_warmup()

Session 6: Neural Network Architectures

Architectures designed for different data structures, from basic to advanced.

Interview answer (30 sec)

I choose the architecture by data type: MLP for tabular, CNN for images (local patterns, shared weights), LSTM/GRU for sequences (gates fix vanishing gradients), Transformers for long-range context and parallel training, autoencoders/VAE/GAN/diffusion for generation, ResNet skip connections for very deep networks, and U-Net for segmentation.

Diagram: CNN pipeline
Image→Conv2d→ReLU→MaxPool2d→Conv2d + ReLU + Pool→Flatten→Linear→Softmax
Diagram: RNN/LSTM unrolled
x₁→LSTM cell (h₀, c₀)→x₂→LSTM cell (h₁, c₁)→… x_t→Final h_t→Linear → output
Diagram: Autoencoder
Input→Encoder→Latent z→Decoder→Reconstruction (loss = MSE)

ANN / MLP

1. Single-layer perceptron

≈ 15 sec spoken

One layer of weights with an activation, mapping inputs directly to outputs. It can only learn linearly separable functions (AND, OR, not XOR). It is the building block for everything bigger and the right starting point to explain neurons.

2. Multilayer perceptron

≈ 15 sec spoken

An MLP stacks several dense layers with non-linear activations. Hidden layers let it learn non-linear boundaries, so it solves XOR and, by the universal approximation theorem, approximates any continuous function. It is the standard model for tabular data.

3. Forward propagation

≈ 15 sec spoken

Pass the input through each layer: z = Wa + b, a = f(z), until the output. Store z and a for the backward pass. For a batch it is a few matrix multiplications.

Methods
nn.Linear(), outputs = model(x)

4. Backpropagation

≈ 15 sec spoken

Compute the output error (ŷ − y for softmax with cross-entropy) and propagate it backward: δ_prev = (Wᵀδ) ⊙ f′(z). Weight gradient is δ·a_prevᵀ and bias gradient is δ. Then the optimizer updates every layer.

Methods
loss.backward(), tf.GradientTape()

5. Weight initialization

≈ 15 sec spoken

Initialization sets the starting weights. Zeros create symmetry, and large values saturate activations. Use Xavier/Glorot for tanh/sigmoid and He (Kaiming) for ReLU so signal and gradient variance stay stable across layers.

Methods
nn.init.xavier_uniform_(), nn.init.kaiming_normal_()

6. Network training

≈ 15 sec spoken

The loop is: shuffle data, take a mini-batch, forward pass, compute loss, zero gradients, backward pass, optimizer step. After each epoch evaluate on validation, log metrics, checkpoint the best model, and stop early when validation stalls.

CNN

7. Convolution

≈ 20 sec spoken

Convolution slides a small filter over the input and computes a dot product at each position. Weights are shared across positions, so it detects a pattern anywhere with far fewer parameters than a dense layer and respects local spatial structure. Output size = (n + 2p − k)/s + 1.

Methods
nn.Conv2d(in, out, kernel_size, stride, padding)

8. Filters and kernels

≈ 15 sec spoken

A kernel (e.g., 3×3) is a small learnable weight matrix. Each filter produces one feature map; a layer has many filters. Early layers learn edges and colors, deeper layers learn textures, parts and objects. 3×3 kernels are standard (VGG-style).

9. Padding

≈ 15 sec spoken

Padding adds zeros around the border. 'valid' means no padding, so the output shrinks; 'same' keeps size equal (with stride 1). It also lets edge pixels contribute equally.

Methods
padding='same' / padding=1

10. Stride

≈ 15 sec spoken

Stride is how many pixels the filter moves each step. Stride 1 keeps resolution; stride 2 halves it, which downsamples and reduces computation. Often used instead of pooling.

Methods
stride=2

11. Pooling

≈ 15 sec spoken

Pooling summarizes a neighbourhood: max pooling keeps the strongest activation, average pooling the mean. It reduces spatial size, adds small translation invariance, and cuts computation. No learnable parameters. Global average pooling often replaces flatten plus dense layers.

Methods
nn.MaxPool2d(2), nn.AvgPool2d()

12. Feature maps

≈ 15 sec spoken

A feature map is the output of one filter applied to the input: a grid showing where that pattern appears. A layer with 64 filters outputs 64 feature maps. Visualizing them helps debug what the CNN has learned.

13. Flattening

≈ 15 sec spoken

Flattening reshapes the final feature maps into a 1-D vector, so dense layers can use them. Example: 7×7×64 becomes 3136 values. It discards spatial structure, which is why modern models prefer global average pooling.

Methods
nn.Flatten()

14. Fully connected layers

≈ 15 sec spoken

Dense layers at the end of a CNN combine the extracted features and produce class scores. They hold most of the parameters in older CNNs such as VGG, so modern networks reduce or remove them.

Methods
nn.Linear()

15. Batch normalization

≈ 15 sec spoken

BatchNorm normalizes each channel using batch mean and variance, then scales and shifts with learnable γ and β. It stabilizes training, allows higher learning rates, and gives mild regularization. At inference it uses running averages, so remember model.eval().

Methods
nn.BatchNorm2d()

16. Dropout

≈ 15 sec spoken

Dropout randomly zeros neurons with probability p during training and scales the rest, so the network cannot depend on any single unit. It acts like averaging many sub-networks. It is switched off at inference. Typical p = 0.2–0.5.

Methods
nn.Dropout(p=0.5)

17. CNN architecture

≈ 15 sec spoken

A CNN stacks blocks of Conv → BatchNorm → ReLU → Pool, doubling filters while halving spatial size, then ends with global pooling and dense layers with softmax. Evolution: LeNet, AlexNet, VGG, ResNet, EfficientNet.

RNN

18. Recurrent connections

≈ 20 sec spoken

An RNN feeds its hidden state back into itself at the next time step: hₜ = tanh(Wₓxₜ + Wₕhₜ₋₁ + b). The same weights are reused at every step, so it handles sequences of any length with a fixed number of parameters.

Methods
nn.RNN()

19. Hidden states

≈ 20 sec spoken

The hidden state is the network's memory: a vector that summarizes the sequence seen so far. Its final value can represent the whole sequence for classification, and all steps can feed a decoder. Its fixed size is a bottleneck for long sequences.

20. Sequential processing

≈ 15 sec spoken

An RNN must process token t before t+1, so computation cannot be parallelized across time, and training on long sequences is slow. Backpropagation through time unrolls the network. This limit is a key reason Transformers replaced RNNs.

21. Vanishing and exploding gradients

≈ 15 sec spoken

Backprop through many time steps multiplies many factors. If they are below 1 the gradient vanishes, so the network forgets long-range dependencies; above 1 it explodes. Fixes: LSTM/GRU gates, gradient clipping, good initialization, ReLU, residual connections, normalization.

Methods
clip_grad_norm_(), use LSTM/GRU

LSTM

22. Forget gate

≈ 20 sec spoken

The forget gate fₜ = σ(W_f[hₜ₋₁, xₜ] + b_f) outputs values between 0 and 1 per cell dimension: 0 erases old memory and 1 keeps it. It lets the LSTM drop irrelevant context, such as the subject of a finished sentence.

Methods
nn.LSTM() internals: f = sigmoid(W_f[h, x] + b_f)

23. Input gate

≈ 15 sec spoken

The input gate iₜ decides how much of the new candidate memory c̃ₜ = tanh(…) is written to the cell state. Together with the forget gate: cₜ = fₜ⊙cₜ₋₁ + iₜ⊙c̃ₜ.

24. Output gate

≈ 15 sec spoken

The output gate oₜ decides which part of the cell state is exposed as the hidden state: hₜ = oₜ ⊙ tanh(cₜ). It controls what the next layer sees.

25. Cell state

≈ 15 sec spoken

The cell state is the LSTM's long-term memory. It is updated additively (forget and input), so gradients flow along it with little attenuation, which is how LSTM solves vanishing gradients, like a conveyor belt through time.

Methods
nn.LSTM() returns (output, (h_n, c_n))

26. Hidden state

≈ 15 sec spoken

The hidden state hₜ is the short-term output at each step. It goes to the next time step, the next layer and the output head. Cell state holds long-term memory; hidden state is the filtered, visible summary.

GRU

27. Update gate

≈ 15 sec spoken

In a GRU, the update gate z decides how much of the previous state to keep versus replace with the new candidate: hₜ = (1 − z)⊙hₜ₋₁ + z⊙h̃ₜ. It plays the role of forget plus input gates together.

Methods
nn.GRU() internals: z_t

28. Reset gate

≈ 15 sec spoken

The reset gate r controls how much of the previous hidden state is used when computing the candidate state. A value near 0 lets the unit ignore history and start fresh, useful at topic boundaries.

29. LSTM vs GRU

≈ 20 sec spoken

GRU has two gates and no separate cell state, so fewer parameters, faster training and good performance on smaller data. LSTM has three gates plus a cell state and can be better on long, complex sequences. In practice results are close, so try both.

Advanced Architectures

30. Autoencoders

≈ 15 sec spoken

An autoencoder has an encoder compressing input into a small latent code and a decoder reconstructing the input, trained with reconstruction loss. Uses: dimensionality reduction, denoising, and anomaly detection, where high reconstruction error flags unusual samples.

Methods
encoder / decoder nn.Module, loss = MSE(recon, x)

31. Variational Autoencoders

≈ 20 sec spoken

A VAE encodes the input to a mean and variance of a latent Gaussian, samples z = μ + σ·ε (the reparameterization trick), and decodes. Loss = reconstruction + KL to the prior N(0, I). The smooth latent space lets you generate new data by sampling.

Methods
reparameterize: z = mu + std * eps; loss = recon + KL

32. GANs

≈ 20 sec spoken

A GAN pits a generator (noise → fake sample) against a discriminator (real vs fake) in a minimax game. When the discriminator is fooled, fakes look real. Strong image quality but training is unstable: mode collapse and vanishing gradients; WGAN and spectral norm help.

Methods
generator / discriminator, BCELoss, two optimizers

33. Diffusion Models

≈ 20 sec spoken

Diffusion models add Gaussian noise to data over many steps (forward), and train a network (usually a U-Net) to predict the noise so they can reverse it (denoise) step by step from pure noise to an image. Stable and high quality, but sampling is slow; text conditioning gives Stable Diffusion.

Methods
diffusers: DDPMScheduler, UNet2DModel

34. Residual Networks (ResNet)

≈ 15 sec spoken

ResNet adds skip connections: output = F(x) + x. The block learns a residual, and the identity path gives gradients a direct route, so very deep networks (50, 101, 152 layers) train without degradation. A key idea reused in Transformers.

Methods
torchvision.models.resnet50(weights=...)

35. DenseNet

≈ 15 sec spoken

In DenseNet each layer receives the concatenated feature maps of all earlier layers. This encourages feature reuse, strengthens gradient flow and needs fewer parameters, at the cost of higher memory usage.

Methods
torchvision.models.densenet121()

36. EfficientNet

≈ 15 sec spoken

EfficientNet uses compound scaling to grow depth, width and input resolution together with a fixed ratio, starting from a NAS-found base (B0). It reaches top accuracy with far fewer parameters and FLOPs than older CNNs.

Methods
torchvision.models.efficientnet_b0()

37. U-Net

≈ 20 sec spoken

U-Net is an encoder-decoder with skip connections from encoder to decoder layers at the same resolution. The encoder captures context, the decoder restores resolution, and skips preserve fine details. Standard for medical and semantic segmentation, and the backbone of diffusion models.

Methods
segmentation_models_pytorch.Unet()

Session 7: Transformers and Attention

The architecture behind modern LLMs, vision and speech models.

Interview answer (30 sec)

Self-attention lets every token look at every other token: softmax(QKᵀ/√d)V. Multi-head attention captures different relations, positional encoding adds order, and masking keeps decoders autoregressive. BERT is encoder-only for understanding, GPT decoder-only for generation, T5 encoder-decoder, and ViT applies it to image patches. I usually fine-tune pretrained models, often with LoRA.

Diagram: Transformer encoder block
Tokens→Embedding + Positional Encoding→Multi-Head Self-Attention: softmax(QKᵀ/√d)V→Add & LayerNorm→Feed-Forward (GELU)→Add & LayerNorm→Repeat N layers

1. Sequence-to-sequence architecture

≈ 20 sec spoken

Seq2seq maps one sequence to another of different length, such as translation or summarization. An encoder reads the input and creates a representation, and a decoder generates the output token by token. Early versions used RNNs with a single context vector, which was a bottleneck that attention solved.

2. Encoder and decoder

≈ 15 sec spoken

The encoder processes the full input with bidirectional self-attention and produces contextual embeddings. The decoder generates outputs autoregressively using masked self-attention and cross-attention over the encoder outputs. BERT is encoder-only, GPT decoder-only, T5 uses both.

3. Attention mechanism

≈ 15 sec spoken

Attention lets the model weigh which input positions matter for each output. It computes similarity scores, softmax-normalizes them into weights, and returns a weighted sum of values. This removes the fixed-size bottleneck and lets it connect distant tokens directly.

Methods
F.scaled_dot_product_attention()

4. Self-attention

≈ 20 sec spoken

In self-attention each token creates a query, key and value; its output is a weighted sum of all tokens' values, with weights from softmax(QKᵀ/√d). Every token sees every other token in one step, so long-range dependencies are easy and it parallelizes well. Cost is O(n²) in sequence length.

5. Multi-head attention

≈ 15 sec spoken

Instead of one attention, we run h heads in parallel with different learned projections, each working in a smaller subspace (d/h), then concatenate and project. Different heads learn different relations, such as syntax, coreference and position.

Methods
nn.MultiheadAttention(embed_dim, num_heads)

6. Query, Key and Value

≈ 25 sec spoken

Think of a search: the query is what I am looking for, keys are labels of items, and values are the content. Q, K, V are linear projections of the input: Q = XW_Q, K = XW_K, V = XW_V. Score = QKᵀ/√d, weights = softmax(score), output = weights·V. Dividing by √d keeps softmax from saturating.

Methods
Q = x @ Wq, K = x @ Wk, V = x @ Wv

7. Positional encoding

≈ 15 sec spoken

Attention has no sense of order, so we add position information to the embeddings. The original Transformer used sinusoidal encodings; BERT learns position embeddings; modern LLMs use rotary (RoPE) or ALiBi, which handle longer contexts better.

Methods
sinusoidal / nn.Embedding(max_len, d) / RoPE

8. Masked attention

≈ 15 sec spoken

A causal mask sets scores for future tokens to −∞ before softmax, so each position can only attend to previous ones. This allows parallel training of a decoder while preserving left-to-right generation. Padding masks also hide pad tokens.

9. Cross-attention

≈ 20 sec spoken

In cross-attention the queries come from the decoder, while keys and values come from the encoder output. This is how the decoder looks at the source sentence while generating a translation. It is also how text conditions image generation in diffusion models.

10. Transformer architecture

≈ 20 sec spoken

Each block has multi-head self-attention then a position-wise feed-forward network, each wrapped with a residual connection and layer norm. Blocks are stacked N times. No recurrence, so training is parallel and scales to huge models; this is the base of modern LLMs.

Methods
nn.TransformerEncoder(), nn.TransformerDecoder()

11. BERT

≈ 20 sec spoken

BERT is an encoder-only model trained with masked language modelling (predict hidden words) and next-sentence prediction. It reads context both ways, producing rich embeddings. Fine-tune with a small head for classification, NER, QA. It is not suitable for free text generation.

Methods
BertModel.from_pretrained('bert-base-uncased')

12. GPT

≈ 15 sec spoken

GPT is a decoder-only Transformer trained to predict the next token (causal language modelling). Scaled up with instruction tuning and RLHF, it becomes a general assistant. It generates text autoregressively, supporting few-shot prompting.

Methods
GPT2LMHeadModel.from_pretrained('gpt2')

13. T5

≈ 15 sec spoken

T5 treats every NLP task as text-to-text with an encoder-decoder Transformer, using a prefix like 'translate English to German:'. A unified format makes multi-task training and transfer simple. Pretrained with span corruption.

Methods
T5ForConditionalGeneration.from_pretrained()

14. Vision Transformer (ViT)

≈ 20 sec spoken

ViT splits an image into patches (e.g., 16×16), linearly embeds each as a token, adds position embeddings and a class token, and feeds them to a standard Transformer encoder. With large-scale pretraining it matches or beats CNNs, but needs more data because it lacks CNN's inductive biases.

Methods
ViTForImageClassification.from_pretrained()

15. Fine-tuning pretrained models

≈ 20 sec spoken

Start from a pretrained model and adapt it using a small task dataset with a low learning rate (1e-5 to 5e-5). Options: full fine-tuning, freezing lower layers, or parameter-efficient methods like LoRA and adapters which train under 1% of parameters. Watch out for catastrophic forgetting.

Methods
Trainer.train(), peft.get_peft_model() (LoRA)

Session 8: Deep Learning for Different Data Types

How preprocessing and models differ per modality.

Interview answer (30 sec)

Each modality needs its own preprocessing: scaling and embeddings for tabular, tokenization and embeddings or Transformers for text, normalization, augmentation and CNN/ViT for images, spectrograms/MFCC for audio, and frame sampling plus 3D CNN or video Transformers for video. Transfer learning is my default when data is limited.

Diagram: Generic pipeline per modality
Raw data (tabular / text / image / audio / video)→Preprocess (scale / tokenize / resize / MFCC / frames)→Model (MLP / Transformer / CNN-ViT / Whisper / 3D-CNN)→Prediction

Structured Data

1. ANN / MLP

≈ 15 sec spoken

For structured data an MLP takes the feature vector and learns non-linear interactions. It needs scaled numeric inputs and encoded categoricals. Compare against gradient boosting, which often wins on small tabular data.

2. Tabular neural networks

≈ 20 sec spoken

Tabular nets embed each categorical column with nn.Embedding, concatenate with scaled numerics and feed an MLP. Architectures such as TabNet and FT-Transformer exist. They help with very large data and multi-modal inputs but XGBoost or LightGBM is the baseline to beat.

Methods
nn.Embedding for categories, StandardScaler, pd.get_dummies()

3. Feature preprocessing

≈ 15 sec spoken

Impute missing values, scale numerics (StandardScaler/MinMax), encode categoricals (one-hot or embeddings), handle outliers and skew (log transform). Fit the scalers on the training set only, then apply to validation/test to prevent data leakage. Save the pipeline for inference.

Text / NLP

4. Text cleaning

≈ 15 sec spoken

Typical steps: lowercase, remove HTML, URLs and extra spaces, handle emojis and contractions, optionally remove stop words and lemmatize. For Transformers, keep cleaning minimal because the tokenizer and model handle raw text well.

5. Tokenization

≈ 15 sec spoken

Tokenization splits text into units and maps them to IDs. Word-level has huge vocabularies and unknown-word problems; subword methods (BPE, WordPiece, SentencePiece) balance both. Always use the tokenizer that matches the pretrained model and handle padding, truncation and attention masks.

Methods
AutoTokenizer.from_pretrained(), tokenizer(text)

6. Word embeddings

≈ 15 sec spoken

Embeddings map words to dense vectors (50–300 dims) where similar meanings are close, replacing sparse one-hot vectors. Static ones (Word2Vec, GloVe) give one vector per word; contextual ones (BERT) change with the sentence ('bank' of a river vs a bank).

Methods
nn.Embedding(vocab, dim)

7. Word2Vec

≈ 15 sec spoken

Word2Vec learns embeddings with a shallow network: CBOW predicts a word from its context, Skip-gram predicts context from a word. Trained with negative sampling. Famous result: king − man + woman ≈ queen.

Methods
gensim.models.Word2Vec()

8. GloVe

≈ 15 sec spoken

GloVe factorizes the global word co-occurrence matrix so vector dot products approximate log co-occurrence counts. It uses corpus-wide statistics, where Word2Vec uses local windows. Pretrained vectors (50–300d) are freely available.

9. FastText

≈ 15 sec spoken

FastText represents a word as the sum of its character n-gram vectors. It can build vectors for rare, misspelled or unseen words and works well for morphologically rich languages. It also has a very fast text classifier.

Methods
gensim.models.FastText()

10. RNN, LSTM, GRU

≈ 15 sec spoken

Before Transformers these handled sequences: embedding layer → LSTM/GRU (often bidirectional) → dense. Good for sentiment, tagging and time series with moderate data, but slow to train and weak on very long dependencies.

11. Transformers

≈ 15 sec spoken

Transformers replace recurrence with self-attention, so they train in parallel and capture long-range context. Pretrained on huge text then fine-tuned, they are the state of the art for nearly all NLP tasks and power LLMs.

12. BERT

≈ 15 sec spoken

For NLP tasks I fine-tune BERT: tokenize with the matching tokenizer, add a classification head on the [CLS] output, train with a small learning rate for 2–4 epochs. Strong for classification, NER and question answering.

Methods
BertModel.from_pretrained('bert-base-uncased')

Images / Computer Vision

13. Image preprocessing

≈ 15 sec spoken

Resize to a fixed size, scale pixels to 0–1, normalize with ImageNet mean/std when using pretrained models, and convert to channel-first tensors. Augment only the training set (flip, crop, color jitter). Keep the exact preprocessing at inference.

Methods
transforms.Compose([Resize, ToTensor, Normalize])

14. CNN

≈ 15 sec spoken

CNNs exploit locality and weight sharing to learn spatial features: convolutions, activation, pooling, then classification. They remain efficient for images, especially with small or medium datasets.

15. Transfer learning

≈ 15 sec spoken

Reuse a model pretrained on ImageNet: replace the final layer, freeze the backbone and train the head, then optionally unfreeze some layers with a low learning rate. It needs far less data and time, and usually beats training from scratch.

Methods
freeze: p.requires_grad = False; replace model.fc

16. ResNet

≈ 15 sec spoken

ResNet uses skip connections so very deep networks train well. ResNet-50 is the classic backbone for classification, detection and transfer learning, and a strong baseline.

17. EfficientNet

≈ 15 sec spoken

EfficientNet scales depth, width and resolution together for the best accuracy per compute. EfficientNet-B0 to B7 let you choose a size by latency budget, and it is a good choice for mobile and cost-sensitive deployment.

Methods
torchvision.models.efficientnet_b0()

18. YOLO

≈ 20 sec spoken

YOLO (You Only Look Once) detects objects in a single forward pass: the image is divided into a grid, and each cell predicts boxes, confidences and classes. Very fast, so suited to real-time video. Non-max suppression removes duplicates. Evaluate with mAP.

Methods
ultralytics.YOLO('yolov8n.pt').train()

19. Object detection

≈ 15 sec spoken

Detection finds what and where: class labels plus bounding boxes. Two-stage detectors (Faster R-CNN) are accurate, while one-stage (YOLO, SSD, RetinaNet) are faster. Key concepts: anchors, IoU, NMS, mAP.

20. Image segmentation

≈ 15 sec spoken

Segmentation classifies every pixel. Semantic segmentation labels classes (U-Net, DeepLab), instance segmentation separates individual objects (Mask R-CNN), and panoptic combines both. Evaluate with IoU and Dice.

21. Vision Transformers

≈ 15 sec spoken

ViT treats image patches as tokens in a Transformer. With large pretraining it excels, and models like Swin add hierarchical windows for efficiency. Pick ViT with big data, CNN when data is small.

Audio

22. Waveforms

≈ 15 sec spoken

A waveform is raw audio amplitude over time, sampled at a rate such as 16 kHz (16,000 numbers per second). It is high-dimensional, so we often convert it into a spectrogram or feed it to models like wav2vec 2.0 directly.

23. Spectrograms

≈ 15 sec spoken

A spectrogram shows frequency content over time, computed with the short-time Fourier transform. The mel scale mimics human hearing. Treated as an image, it can be fed to a CNN for classification or ASR.

Methods
librosa.stft(), torchaudio.transforms.MelSpectrogram()

24. MFCC

≈ 15 sec spoken

MFCCs are compact coefficients derived from the log mel spectrogram via a DCT, capturing the spectral envelope of speech. Classic features for speech and speaker recognition; deep models often use raw mel-spectrograms instead.

Methods
librosa.feature.mfcc()

25. Speech recognition

≈ 15 sec spoken

ASR converts speech to text. Pipeline: audio → features (mel-spectrogram) → acoustic model (Transformer/Conformer) → decoder (CTC or seq2seq) → text. Measured with Word Error Rate (WER).

26. Whisper

≈ 15 sec spoken

Whisper is OpenAI's encoder-decoder Transformer trained on 680k hours of multilingual audio. It handles transcription, translation and language detection robustly with noise and accents. Sizes range from tiny to large.

Methods
whisper.load_model('base').transcribe()

27. Wav2Vec2

≈ 15 sec spoken

Wav2Vec2 learns speech representations through self-supervised pretraining on unlabelled audio (contrastive task), then is fine-tuned with CTC on a little labelled data. Great for low-resource languages.

Methods
Wav2Vec2ForCTC.from_pretrained()

Video

28. Frame extraction

≈ 15 sec spoken

Videos are sequences of images, so we sample frames (every k-th or uniformly N frames) with OpenCV, resize and normalize them. Sampling choices trade temporal detail against compute.

Methods
cv2.VideoCapture(), cap.read()

29. 3D CNN

≈ 15 sec spoken

3D convolutions use kernels over height, width and time, so they learn motion and spatio-temporal features directly (C3D, I3D, SlowFast). They are accurate but heavy on compute and memory.

Methods
nn.Conv3d()

30. CNN + LSTM

≈ 15 sec spoken

A CNN extracts features from each frame, and an LSTM models their order over time to classify actions. It is cheaper than 3D CNNs, though it handles very long videos less well.

31. Video Transformers

≈ 15 sec spoken

Models like TimeSformer and ViViT split video into spatio-temporal patches and use attention across space and time, often with factorized attention to control the O(n²) cost. They are state of the art but data-hungry.

Session 9: Regularization and Model Improvement

Techniques to generalize better and train more reliably.

Interview answer (30 sec)

To fix overfitting I use dropout, L2/weight decay, early stopping, data augmentation, and transfer learning; BatchNorm/LayerNorm stabilize training, gradient clipping prevents exploding gradients, and class weights or focal loss handle imbalance. I tune hyperparameters with Optuna, one change at a time.

Diagram: Fixing overfitting
Train loss ↓, val loss ↑→Dropout, L2, augmentation→Early stopping→Better generalization

1. Dropout

≈ 15 sec spoken

Dropout zeros each neuron with probability p during training, forcing redundancy and acting like an ensemble of sub-networks. It is turned off in eval mode. Typical p is 0.2–0.5; apply it after dense layers and less in CNNs.

Methods
nn.Dropout(p=0.5)

2. L1 and L2 regularization

≈ 20 sec spoken

They add a penalty on weights to the loss: L1 adds λΣ|w| and creates sparse weights (feature selection); L2 adds λΣw² and shrinks weights smoothly. L2 is the usual default and ties to a Gaussian prior; L1 to a Laplace prior.

Methods
loss + lambda * w.abs().sum(); optimizer weight_decay

3. Weight decay

≈ 15 sec spoken

Weight decay shrinks weights by a small factor each step: w ← w − η(g + λw). With SGD it equals L2, but with Adam they differ, so use AdamW with decoupled weight decay. Typical values 1e-4 to 1e-2.

Methods
optim.AdamW(weight_decay=...)

4. Batch Normalization

≈ 15 sec spoken

BatchNorm normalizes activations across the batch for each feature, with learnable scale and shift. It speeds training, permits larger learning rates and regularizes slightly. It depends on batch size, so with small batches use GroupNorm or LayerNorm.

Methods
nn.BatchNorm1d()

5. Layer Normalization

≈ 15 sec spoken

LayerNorm normalizes across the features of a single sample, so it does not depend on batch size. It is standard in Transformers and RNNs, where batch statistics are awkward with variable sequence lengths.

Methods
nn.LayerNorm()

6. Early stopping

≈ 15 sec spoken

Monitor validation loss and stop when it has not improved for 'patience' epochs, then restore the best weights. It is simple, free regularization that also saves compute.

Methods
keras EarlyStopping(patience=5, restore_best_weights=True)

7. Data augmentation

≈ 15 sec spoken

Create modified copies of training data to increase diversity: flips, crops, rotations, color jitter, Mixup/CutMix for images; noise, SpecAugment for audio; synonym swaps or back-translation for text. Apply to training data only, and keep labels valid.

Methods
transforms.RandomHorizontalFlip(), RandomCrop(), ColorJitter()

8. Transfer learning

≈ 15 sec spoken

Initialize with a pretrained model's weights so you inherit general features and need much less data. It is the first thing I try for images and text with limited labelled data.

Methods
freeze: p.requires_grad = False; replace model.fc

9. Fine-tuning

≈ 15 sec spoken

Fine-tuning trains pretrained weights on your task, often unfreezing gradually (head first, then upper layers) with discriminative learning rates. Use a lower rate than from-scratch training, and consider LoRA for large models.

10. Hyperparameter tuning

≈ 15 sec spoken

Tune the learning rate first, then batch size, architecture size, dropout and weight decay. Random search or Bayesian optimization (Optuna) beats grid search. Use a validation set or cross-validation, and track runs in MLflow.

Methods
optuna.create_study(), study.optimize()

11. Gradient clipping

≈ 15 sec spoken

Clip the gradient norm to a maximum (e.g., 1.0) before the optimizer step, so one bad batch cannot blow up the weights. Essential for RNNs and common in Transformer training.

Methods
torch.nn.utils.clip_grad_norm_(params, 1.0)

12. Class imbalance handling

≈ 15 sec spoken

Options: class weights, resampling (SMOTE, undersampling), focal loss, balanced batch sampling, and threshold tuning. Always evaluate with precision, recall, F1 and PR-AUC rather than accuracy.

Methods
CrossEntropyLoss(weight=w), WeightedRandomSampler, imblearn SMOTE

Session 10: Deep Learning Evaluation

Measuring model quality using metrics that match the business goal.

Interview answer (30 sec)

The metric must match the business cost. Accuracy fails on imbalanced data, so I use precision, recall, F1 and PR-AUC; regression uses MAE/RMSE/R²; segmentation uses IoU/Dice; generation uses BLEU/ROUGE/perplexity. I always evaluate on a held-out test set.

Diagram: Classification metrics
Predictions→Confusion matrix (TP FP FN TN)→Precision / Recall→F1→Threshold tuning→ROC-AUC / PR-AUC

Classification

1. Accuracy

≈ 15 sec spoken

Accuracy = correct predictions / total. It is simple but misleading with imbalanced classes: 99% accuracy on 1% fraud may mean the model catches nothing. Use it only for balanced data.

Methods
accuracy_score()

2. Precision

≈ 15 sec spoken

Precision = TP/(TP + FP): of everything flagged positive, how much is truly positive. Prioritize it when false alarms are costly, such as spam filters blocking real mail or recommending wrong items.

Methods
precision_score()

3. Recall

≈ 15 sec spoken

Recall = TP/(TP + FN): of all real positives, how many were found. Prioritize it when misses are costly: cancer screening, fraud, safety incidents.

Methods
recall_score()

4. F1-score

≈ 15 sec spoken

F1 = 2PR/(P + R), the harmonic mean, which is high only if both precision and recall are high. Good single number for imbalanced classification. Macro-F1 averages classes equally; weighted-F1 by support.

Methods
f1_score()

5. Confusion matrix

≈ 15 sec spoken

A table of TP, FP, FN, TN (or per-class counts for multiclass). It shows which classes are confused, and all other classification metrics derive from it. Always inspect it before trusting one number.

Methods
confusion_matrix(), classification_report()

6. ROC-AUC

≈ 20 sec spoken

ROC plots true positive rate against false positive rate across thresholds, and AUC is the area: the probability that a random positive is ranked above a random negative. 0.5 is random and 1.0 perfect. It can look optimistic on heavily imbalanced data.

Methods
roc_auc_score()

7. PR-AUC

≈ 15 sec spoken

The precision-recall curve plots precision against recall across thresholds; its area (average precision) focuses on the positive class. It is more informative than ROC-AUC when positives are rare.

Methods
average_precision_score()

Regression

8. MAE

≈ 15 sec spoken

Mean absolute error is the average of |y − ŷ|, in the same units as the target and easy to explain to the business ('off by ₹5,000 on average'). Robust to outliers.

Methods
mean_absolute_error()

9. MSE

≈ 15 sec spoken

Mean squared error averages the squared errors, penalizing large mistakes. Good when big errors are especially bad; units are squared.

Methods
mean_squared_error()

10. RMSE

≈ 15 sec spoken

RMSE is √MSE, bringing the error back to the target's units while still emphasizing large errors. Always RMSE ≥ MAE; a big gap signals outliers.

Methods
np.sqrt(mean_squared_error())

11. R²

≈ 15 sec spoken

R² = 1 − SS_res/SS_tot: the fraction of variance explained, 1 is perfect and 0 equals predicting the mean (it can go negative). It does not show whether predictions are unbiased, so pair it with MAE/RMSE.

Methods
r2_score()

Specialized evaluation

12. IoU

≈ 15 sec spoken

Intersection over Union = overlap area / union area of predicted and true boxes or masks. In detection, a prediction counts as correct above a threshold (e.g., 0.5), and mAP averages precision over thresholds and classes.

Methods
torchmetrics.JaccardIndex()

13. Dice Score

≈ 15 sec spoken

Dice = 2|A∩B| / (|A| + |B|). Like IoU but weights overlap more, and it is popular in medical segmentation and also used as a loss (Dice loss) for small foreground regions.

Methods
torchmetrics.Dice()

14. BLEU

≈ 15 sec spoken

BLEU measures n-gram precision between machine output and reference translations with a brevity penalty. Standard for machine translation, but it ignores meaning and synonyms.

Methods
sacrebleu.corpus_bleu()

15. ROUGE

≈ 15 sec spoken

ROUGE measures n-gram or longest-common-subsequence recall against reference summaries (ROUGE-1, -2, -L). Used for summarization; it also misses semantic equivalence.

Methods
rouge_score.rouge_scorer

16. Perplexity

≈ 15 sec spoken

Perplexity = exp(average cross-entropy): how 'surprised' a language model is by held-out text; lower is better. It is the effective branching factor, useful to compare LMs with the same tokenizer.

Methods
torch.exp(cross_entropy_loss)

Choosing a metric

17. Business mapping

≈ 15 sec spoken

Map metric to cost: fraud or disease → recall and PR-AUC; spam or legal flagging → precision; balanced tasks → accuracy/F1; ranking → ROC-AUC/NDCG; forecasting → MAE/RMSE/MAPE; detection → mAP; segmentation → Dice/IoU; generation → BLEU/ROUGE/human eval.

Session 12: Production-Level Deep Learning and MLOps

Taking models from notebooks to reliable services.

Interview answer (30 sec)

In production I build a reproducible pipeline: Dataset/DataLoader, GPU with mixed precision, checkpoints, MLflow tracking and a registry, then optimize (quantization, pruning, ONNX), serve with FastAPI in Docker on Kubernetes, and monitor for data and concept drift with CI/CD and retraining.

Diagram: MLOps loop
Code + Data→Train (GPU, AMP)→MLflow tracking→Model registry→Docker image→Kubernetes serving→Monitor drift→Retrain

1. PyTorch training pipelines

≈ 20 sec spoken

A clean pipeline has a Dataset and DataLoader, a model, a loss, an optimizer and scheduler, and a loop with model.train(), forward, loss, zero_grad, backward, step, then model.eval() with no_grad for validation. Add logging, checkpointing, seeds and config files. Libraries like PyTorch Lightning reduce boilerplate.

Methods
Dataset, DataLoader, model.train(), loss.backward(), optimizer.step(), model.eval()

2. TensorFlow/Keras training pipelines

≈ 15 sec spoken

Build input pipelines with tf.data (map, shuffle, batch, prefetch), define the model with the functional or Sequential API, compile with optimizer, loss and metrics, and call fit with callbacks (ModelCheckpoint, EarlyStopping, TensorBoard).

Methods
tf.data.Dataset, model.compile(), model.fit(), callbacks

3. GPU and CUDA

≈ 20 sec spoken

GPUs have thousands of cores suited to matrix math. CUDA is NVIDIA's programming platform, and cuDNN supplies optimized kernels. In PyTorch move model and data with .to('cuda'). Typical bottlenecks: GPU memory (reduce batch size, use mixed precision) and slow data loading (num_workers, pin_memory).

Methods
torch.cuda.is_available(), model.to('cuda')

4. Mixed precision training

≈ 15 sec spoken

Use FP16 or BF16 for most operations and FP32 for sensitive ones. It speeds up training 2–3× on modern GPUs and halves memory. FP16 needs loss scaling (GradScaler) to avoid underflow, while BF16 is more stable.

Methods
torch.autocast(), GradScaler()

5. Distributed training basics

≈ 15 sec spoken

Data parallelism replicates the model on each GPU, splits batches and averages gradients (DDP). Model, pipeline and tensor parallelism split the model itself for very large models; ZeRO/FSDP shard optimizer states and parameters. Launch with torchrun.

Methods
DistributedDataParallel, torchrun

6. DataLoader and Dataset

≈ 15 sec spoken

A Dataset defines __len__ and __getitem__ for one sample; the DataLoader handles batching, shuffling and parallel loading with num_workers. Use a custom collate_fn for variable-length sequences. Fast data loading prevents idle GPUs.

Methods
__len__, __getitem__, DataLoader(num_workers=4)

7. Checkpointing

≈ 15 sec spoken

Save model state, optimizer state, scheduler, epoch and best metric periodically, so training can resume after failure and the best model is kept. In PyTorch: torch.save(state_dict). Save the best checkpoint by validation metric.

Methods
torch.save(model.state_dict()), model.load_state_dict(torch.load())

Methods
mlflow.log_param(), mlflow.log_metric(), mlflow.pytorch.log_model()

≈ 15 sec spoken

Methods
mlflow.register_model()

≈ 20 sec spoken

15. Model monitoring

≈ 15 sec spoken

Track system metrics (latency, throughput, errors, GPU usage) and model metrics (prediction distribution, accuracy when labels arrive, business KPIs). Set alerts and dashboards (Prometheus, Grafana), and trigger retraining when quality drops.

16. Data drift

≈ 15 sec spoken

Data drift means the input feature distribution changes from training time (new customer segments, sensor changes). Detect with KS test, PSI, or tools like Evidently. It can degrade the model even if the relationship is unchanged.

Methods
evidently, KS test (scipy.stats.ks_2samp)

17. Concept drift

≈ 15 sec spoken

Concept drift means the relationship between inputs and the target changes (fraud patterns evolve, behaviour shifts after a pandemic). It needs ground-truth labels to detect; the fix is retraining on recent data or online learning.

18. Logging and observability

≈ 15 sec spoken

Log requests, predictions, model version and latency with correlation IDs, and add metrics and distributed tracing (OpenTelemetry). Good observability lets you debug a bad prediction and reproduce it. Mind privacy: do not log sensitive data.

19. Model optimization

≈ 15 sec spoken

Reduce latency and cost with quantization, pruning, distillation, operator fusion, batching, caching and compiled runtimes (TensorRT, ONNX Runtime, torch.compile). Always re-check accuracy after optimizing.

20. Quantization

≈ 15 sec spoken

Quantization stores weights (and activations) in lower precision such as INT8 instead of FP32, giving about 4× smaller models and faster inference. Post-training quantization is easy; quantization-aware training keeps accuracy higher. Slight accuracy loss is the trade-off.

Methods
torch.quantization.quantize_dynamic()

21. Pruning

≈ 15 sec spoken

Pruning removes unimportant weights, neurons or filters (usually small magnitude), then fine-tunes. Unstructured pruning gives sparse weights but needs sparse kernels for speedup; structured pruning removes whole channels for real speedups.

Methods
torch.nn.utils.prune.l1_unstructured()

22. ONNX

≈ 15 sec spoken

ONNX is an open model format that lets you train in one framework and run in another, using ONNX Runtime or TensorRT for fast cross-platform inference. Export with torch.onnx.export and validate outputs against the original.

Methods
torch.onnx.export(), onnxruntime.InferenceSession()

23. TorchScript / torch.export

≈ 20 sec spoken

TorchScript (jit.trace or jit.script) serializes a PyTorch model to run without Python, for C++ or mobile. torch.export is the newer approach that captures a full graph for the PyTorch 2 compiler stack. Tracing misses data-dependent control flow, so scripting or export is safer.

Methods
torch.jit.trace(), torch.export.export()

≈ 15 sec spoken

Key concerns: latency vs throughput, dynamic batching, model warm-up, caching, autoscaling, GPU sharing, fallbacks and timeouts, A/B or shadow testing, and monitoring. Serving tools: Triton, TorchServe, TF Serving, vLLM for LLMs.

Session 14: Coding Standards

Every algorithm follows the same learning path.

Interview answer (30 sec)

I always implement from scratch in NumPy first, dry-run it by hand, then match the result in PyTorch and Keras, inspect training curves, save/load the model and expose a prediction API.

Diagram: Coding path
NumPy scratch→Dry run→PyTorch→Keras→Compare results→Save / load→Prediction API

1. 1. NumPy from scratch

≈ 15 sec spoken

Implement the algorithm with only NumPy (e.g., a 2-layer MLP) so every step is visible. It proves you understand the mechanics and not only the framework calls.

2. 2. Line-by-line explanation

≈ 15 sec spoken

Explain what each line does, including shapes and why. In interviews, narrating shapes aloud signals strong fundamentals.

3. 3. Manual dry run

≈ 15 sec spoken

Run one sample with tiny numbers by hand: forward values, loss, gradients and updated weights. It confirms the logic and is excellent for whiteboard rounds.

4. 4. Intermediate calculations

≈ 15 sec spoken

Print z, activations, loss and gradients at each layer for one step, so you can compare them with autograd output and catch bugs early.

5. 5–6. PyTorch and TensorFlow/Keras

≈ 15 sec spoken

Re-implement the same model in PyTorch (nn.Module, optimizer, loop) and Keras (Sequential, compile, fit). Showing both demonstrates framework fluency.

6. 7. Compare results

≈ 15 sec spoken

Check that the scratch, PyTorch and Keras versions give similar loss and accuracy with the same data, init and seed. Differences point to bugs.

7. 8. Training/validation curves

≈ 15 sec spoken

Plot loss and metric per epoch. Both high means underfit; a growing gap means overfit; oscillation means the learning rate is too high; flat means too low or dead neurons.

8. 9. Save and load

≈ 15 sec spoken

Save weights (state_dict or .keras) plus preprocessing and config, then reload and confirm identical predictions. Never pickle whole models across versions without care.

9. 10. Prediction API

≈ 15 sec spoken

Wrap the loaded model in a FastAPI endpoint with a typed schema and test it with curl or pytest. This turns a notebook into a service.

10. Code quality

≈ 15 sec spoken

Use modular functions and classes, type hints, config files, logging, tests and fixed seeds. Production code should be readable, reusable and reproducible.
